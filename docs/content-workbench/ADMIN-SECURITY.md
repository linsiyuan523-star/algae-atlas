# 内容发布工作台管理员安全说明

## 安全边界

- 工作台维护内容记录、正文、图片元数据和离线内容分支。
- 导航、路由、主题、页脚、服务器配置和部署由代码管理员维护。
- 核心草稿、校验、预览、本地提交和 Bundle 流程可完全离线运行。
- 工作台不是远程 Git、GitHub、发布或部署控制台。

## 角色分离

- 内容编辑：创建草稿、填写来源与图片权利信息、请求审核。
- 审核人：核对事实、公开范围、图片许可、alt 和语言状态。
- 本地操作员：选择批准的工作树，核对预演并创建本地内容提交。
- 集成管理员：验证 Bundle，在独立主机整合、测试，并在另行授权后处理远程操作。

一人可承担多个角色，但审核证据和远程授权仍须明确记录。

## 安装候选

- `0.1.0` Windows 候选未签名；必须用交付清单中的 SHA256 识别。
- 安装程序为当前用户范围，不应要求管理员权限。
- 依赖已安装且受支持的 WebView2 Runtime。
- 禁止把测试证书、私钥或签名密码打包到安装目录。

## 本地目录

- 草稿、图片暂存和仓库目录应位于本地受控磁盘。
- 不选择同步盘、公共共享目录、符号链接、junction 或可重解析路径。
- 普通内容操作不提升权限；目录不可写时修正目录所有权或改用合适位置。
- 配置、草稿和日志不得包含 Token、密码、SSH 私钥或真实 `.env`。

## 内容与图片

- 中文可独立进入发布候选；英文 `missing` 时禁止生成 `en.md`。
- 所有引用图片必须有作者或提供者、许可、署名、公开使用范围和发布语言 alt。
- 可识别人物必须有非敏感授权引用；不在元数据中保存证件或联系方式。
- 图片导出前移除隐私元数据；保留原图仅限受控本地恢复用途。
- 来源、作者和审核人使用稳定 ID，禁止伪造已核验状态。

## Git 控制

- 内容候选从干净、无 remote 的批准工作树开始。
- 预演绑定仓库根目录、基础分支、HEAD 和完整目标文件集合。
- 本地提交只创建 `content/YYYYMMDD-<record-id>` 分支和一个内容提交。
- 禁止 `push`、`pull`、合并 `main`、Tag、Release、部署和强制更新。
- 禁止 `git reset --hard`、`git clean -fdx` 和覆盖未知未跟踪文件。

## Bundle 交接

- Bundle 必须包含完整历史、单一批准分支头和 SHA256 sidecar。
- 交接目录必须在源仓库之外且创建前不存在。
- 导入脚本只建立 `import/...` 临时分支，不切换当前分支。
- 集成前复核 Bundle 头、基础提交、变更文件和摘要。
- 摘要、分支或前置提交不一致是停止条件，不能现场猜测适配。

## 网络与凭据

- 离线流程不需要网络，也不应建立应用级远程连接。
- 工作台界面不得索取 GitHub Token、密码或 SSH 私钥。
- 任何未来远程功能必须默认关闭、独立审计，并由用户在专门阶段授权。
- 不把测试内容、日志或图片上传到第三方诊断服务。

## 事件处理

出现摘要不匹配、未知 remote、路径替换、凭据痕迹或异常文件时：

1. 停止提交和导入，断开交付介质。
2. 保留当前只读证据，不执行清理或覆盖。
3. 记录应用版本、分支、HEAD、文件名、摘要和错误代码。
4. 通知集成管理员，使用已知良好 Bundle 和独立目录复核。
5. 在原因与影响范围确认前，不推送、合并、签名或部署。
