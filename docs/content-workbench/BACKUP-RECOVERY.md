# 草稿与离线交付备份恢复

## 备份对象

- 草稿目录：版本化草稿 JSON、中文/英文正文和异常恢复信息。
- 图片暂存目录：处理后的 WebP、缩略图、元数据清单和可选本地原图。
- 配置文件：仅包含本地目录设置；不要把凭据写入配置。
- 内容分支 Bundle、SHA256 文件、`MANIFEST.txt` 和交接说明。

网站仓库已有提交由 Git 和完整 Bundle 保护；未提交草稿必须单独备份。

## 正常备份

1. 等待界面显示草稿和图片元数据已保存。
2. 关闭工作台，避免备份到一半的原子替换文件。
3. 从“设置与诊断”记录当前草稿目录和图片暂存目录。
4. 把两个目录作为同一批次复制到受控离线介质。
5. 复制对应内容 Bundle 和 SHA256 文件。
6. 在另一位置重新计算摘要，并记录备份日期、应用版本和负责人。

不要只备份草稿 JSON：正文文件和图片暂存文件必须与其配套。

## 恢复到原机器

1. 保留当前目录副本，不直接覆盖唯一一份数据。
2. 关闭工作台。
3. 把同一批次的草稿和图片暂存目录恢复到新的空目录。
4. 启动工作台，在设置中选择恢复后的目录。
5. 按提示重启，确认草稿数量、图片数量和目录权限。
6. 打开草稿，检查正文、图片引用、许可、alt 和英文状态。
7. 重新运行仓库预演；不要沿用恢复前的预演确认。

## 恢复到新机器

1. 安装与备份记录匹配的工作台版本，并校验安装程序 SHA256。
2. 准备无 remote 的 bundle 派生网站工作树。
3. 恢复草稿和图片暂存目录，保持文件名与目录层级不变。
4. 完成首次设置并重启。
5. 检查本地诊断后再打开草稿。
6. 对已导出的内容 Bundle 先验摘要，再导入 `import/...` 临时分支。

## 异常退出恢复

- 下次启动出现恢复横幅时，先打开最近草稿并核对更新时间。
- 自动保存版本与人工备份冲突时，两份都保留，逐字段比较后再保存。
- 损坏或未来版本草稿被隔离时，不手工改名覆盖有效草稿。
- 恢复后编辑会使既有审核失效；按界面重新完成审核证据。

## Git 与 Bundle 恢复

1. 校验 Bundle SHA256 和 `git bundle verify`。
2. 在干净测试仓库运行 `Import-Bundle.ps1`。
3. 确认当前分支和 HEAD 未改变，只新增预期 `import/...` 分支。
4. 检查导入分支文件清单和提交信息。
5. 合并、推送和部署仅由集成管理员在独立阶段执行。

## 保留与销毁

- 按团队数据保留策略保存必要备份，限制介质访问。
- 含未公开内容或可识别人物资料的介质不得作为普通共享盘使用。
- 销毁备份属于管理员操作，应先确认副本、保留期限和审批记录。
- 应用默认卸载可能保留草稿；不能把卸载当作安全删除机制。
