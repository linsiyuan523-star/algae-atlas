# 内容发布工作台快速入门

适用版本：Windows `0.1.0` 离线候选。

## 1. 启动前

1. 从管理员提供的离线目录取得安装程序和 SHA256 文件。
2. 用 `Get-FileHash -Algorithm SHA256 <安装程序>` 计算摘要。
3. 仅在摘要与交付清单完全一致时安装。
4. 当前候选未签名；Windows 信誉提示不是摘要校验的替代品。
5. 准备一个干净、无 remote、允许本地提交的网站工作树。

## 2. 首次设置

1. 启动“藻类团队内容发布工作台”。
2. 设置本地网站仓库、草稿目录和图片暂存目录。
3. 确认目录可读写，Git、Node.js 和图片能力诊断可用。
4. 保存配置；如界面提示需要重启，则关闭后重新打开应用。

工作台不会要求 GitHub 登录、Token、SSH 私钥或部署凭据。

## 3. 创建团队动态

1. 在“新建内容”选择“团队动态”。
2. 填写稳定 ID；只用小写字母、数字和连字符，发布后不要更改。
3. 填写中文标题并创建草稿。
4. 保持“英文版本”关闭，此时英文状态应为 `missing`。
5. 填写中文摘要、日期、类别、负责作者稳定 ID、来源和公开范围。
6. 在中文正文中使用二级或更低级标题，不使用一级标题。
7. 完成审核人、审核日期和版本后，依次进入“审核中”和“发布候选”。

“发布候选”表示内容可以离线交接，不表示已部署到网站。

## 4. 添加图片

1. 选择“封面图”并接收第一张图片。
2. 填写作者或提供者、许可标识、许可名称、署名文字、权利状态、使用范围和中文 alt。
3. 保存图片元数据。
4. 选择“正文图”并接收第二张图片，填写同样的权利与 alt 信息。
5. 保存元数据后点击“插入中文正文”。
6. 不把身份证件、联系方式、精确位置或其他敏感信息写入图片元数据。

英文保持 `missing` 时不要求英文 alt，也不会生成 `en.md`。

## 5. 预览

1. 点击“预览详情页”。
2. 分别检查“桌面”和“手机”宽度。
3. 检查标题换行、正文、封面、正文图、alt、署名和许可提示。
4. 切换到 English，确认显示“英文版本缺失”，而不是英文详情页。
5. 返回编辑并保存草稿。

## 6. 本地提交

1. 打开“仓库导出”，选择草稿和本地网站仓库。
2. 点击“诊断并预演”。
3. 仅当 Schema、目标文件、工作区、分支和工具诊断全部通过时继续。
4. 核对新文件清单，确认后创建本地内容分支和单个内容提交。
5. 确认原基础分支没有前移，工作区保持干净。

## 7. 离线交接

1. 在“离线 Bundle 交接”填写刚提交的仓库和一个尚不存在的目标目录。
2. 运行预检，核对分支、HEAD、Bundle 名和改动文件数。
3. 确认后导出交接包。
4. 在另一测试仓库运行交接包内的 `Import-Bundle.ps1`。
5. 确认脚本只创建 `import/...` 临时分支，不切换、合并、推送或部署。
6. 对照 SHA256 文件复核 Bundle，并检查导入分支中的中文正文和图片。

远程推送、Draft PR、合并和部署由独立集成阶段处理。
