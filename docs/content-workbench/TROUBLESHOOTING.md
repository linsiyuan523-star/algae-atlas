# 内容发布工作台故障排查

先停止当前操作，保留草稿、错误文字和最近一次预演结果。不要用强制 Git 命令“清理”现场。

## 安装程序摘要不匹配

- 不要运行安装程序。
- 重新计算 SHA256，确认比较的是同一个文件名和完整 64 个十六进制字符。
- 从管理员提供的离线介质重新取得候选，不从临时聊天或网盘链接替换。

## Windows 提示未知发布者

- `0.1.0` 候选未签名，这是已知限制。
- 先核对 SHA256 和交付清单，再由管理员决定是否继续。
- 摘要不匹配时不得用“仍要运行”绕过。

## 首次启动诊断失败

- Git 或 Node.js 缺失：安装项目规定版本后刷新诊断。
- WebView2 缺失：安装受支持的 Microsoft Edge WebView2 Runtime。
- 目录不可写：选择普通用户可读写的本地目录，不提高应用权限。
- 配置保存后仍使用旧目录：按界面提示重启应用。

## 草稿无法保存

- 检查稳定 ID、中文标题和内容类型。
- 检查审核日期不早于审核更新时间，审核版本使用 `major.minor`。
- 发布候选必须有至少一位审核人，审核状态必须为“已审核”。
- 正文标题从 `##` 开始；移除脚本、活动 HTML 和不安全链接。
- 等待自动保存结束后再关闭窗口。

## 图片阻止发布候选

- 每张被引用图片都要填写作者或提供者、许可名称、署名和中文 alt。
- 权利状态必须为“已确认”，使用范围必须为“公开网站”。
- 含可识别人物时必须确认人物同意，并只填写非敏感授权引用。
- 正文图保存元数据后才能插入正文。
- 图片处理失败时保留原文件，不手工改写暂存清单。

## 英文意外生成

- 关闭英文版本并保存草稿，确认状态显示 `missing`。
- 清空英文正文；`missing` 状态不能携带 `en.md`。
- 导出预演中如出现英文目标，停止并重新检查草稿。

## 仓库预演被阻止

- `WORKTREE_DIRTY`：先辨认并处理现有变更，不使用 `git reset --hard` 或 `git clean -fdx`。
- `REMOTE_PRESENT`：内容候选仓库必须是无 remote 的离线测试仓库。
- `TARGET_EXISTS`：稳定 ID 已占用；不要覆盖已有内容。
- `BRANCH_EXISTS`：目标内容分支已存在；核对是否为同一次任务。
- `PATH_CASE_CONFLICT`：修正大小写冲突，不在 Windows 上强行提交。
- 工具或脚本缺失：确认选择的是网站仓库根目录。

预演结果与当前 HEAD、分支或文件清单不一致时，重新预演，不继续确认。

## Bundle 预检或导入失败

- 源仓库必须位于刚创建的内容分支，工作区干净且无 remote。
- 目标交接目录必须尚不存在，并位于源仓库之外。
- SHA256 不匹配时停止导入，重新取得完整交接目录。
- 导入分支已存在时先核对其 HEAD；不要覆盖或强制更新。
- 导入脚本只允许创建 `import/...` 分支，不允许自动合并或推送。

## 仍无法恢复

记录应用版本、候选 SHA256、草稿稳定 ID、当前分支、HEAD、错误代码和最后 30–60 行关键日志。不要记录 Token、密码、私钥或真实 `.env`。
